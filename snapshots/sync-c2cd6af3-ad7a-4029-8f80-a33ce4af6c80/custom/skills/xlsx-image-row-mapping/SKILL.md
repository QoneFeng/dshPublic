# xlsx 内嵌图片 → 数据行 精确配对

中文报价表（WPS/Excel 导出）几乎都是"图片贴在行旁边"的结构，要把图片导出并按行命名时，
直接上 openpyxl 或简单正则一定会错。下面是在真实 209MB / 17 表 / 434 张图的
《乐归全宅智控价格表》上验证过的完整方法。

## 五个必踩的坑

### 1. 自闭合单元格标签会让正则"吞掉"后续单元格
错误写法：`<c r="([A-Z]+)\d+"([^>]*)(?:/>|>([\s\S]*?)</c>)`
`[^>]*` 会把 ` s="37"/` 里的 `/` 也吃掉，然后 `>` 匹配到**下一个**单元格的 `>`，
导致 A4 的 body 里混进 B4、C4 的内容 —— 表现为"整行数据错位到相邻列"。

正确写法（自闭合分支放前面，属性用 `(?:[^>"]|"[^"]*")*?` 避免跨引号）：
```python
CELL = re.compile(r'<c r="([A-Z]+)\d+"((?:[^>"]|"[^"]*")*?)/>'
                  r'|<c r="([A-Z]+)\d+"((?:[^>"]|"[^"]*")*?)>([\s\S]*?)</c>')
```
第一分支命中 → 空单元格；第二分支命中 → 取 `<v>` 里的值。

### 2. 纵向合并单元格：只有左上角有值
报价表里"产品名称""系列"几乎都纵向合并（如 `B4:B5`、`B18:B20`），
合并区其余行在 XML 里**根本没有这个单元格**。
只按行取值的结果是"每隔一行产品就消失"（磁吸轨道灯 51 行只剩 53 条产品）。

必须解析 `<mergeCells>` 并回填：
```python
for a, b in re.findall(r'<mergeCell ref="([A-Z]+\d+):([A-Z]+\d+)"', sheet_xml):
    c1, r1 = col2num(letter(a)), rownum(a)
    c2, r2 = col2num(letter(b)), rownum(b)
    v = rows.get(r1, {}).get(c1)
    if v not in (None, '') and r2 > r1:
        for rr in range(r1, r2 + 1):
            rows.setdefault(rr, {}).setdefault(c1, v)   # 用 setdefault，别覆盖已有值
```

### 3. WPS 单元格图片（DISPIMG）与浮动图片是两套机制
- 浮动图片：`xl/worksheets/_rels/sheetN.xml.rels` → `xl/drawings/drawingN.xml`
  → `<xdr:from><xdr:row>` 给出锚点行（0 基），`r:embed` 经 `drawingN.xml.rels` 映射到 `xl/media/imageN.ext`。
- 单元格图片：单元格公式为 `=DISPIMG("ID_XXXXXXXX",1)`，
  ID → 图片映射在 `xl/cellimages.xml`（`<xdr:cNvPr name="ID_...">` + `r:embed`）
  → `xl/_rels/cellimages.xml.rels`。

两套都要处理，否则会漏图（本例 434 张浮动图 + 2 张 DISPIMG）。

### 4. 图片"锚点行" ≠ "所属产品行"，必须按系列分块 + 就近单调匹配
作者排版时会把一张图放在系列首行、视觉上跨多行；也可能一个系列 6 个产品只放了 3 张图。
- 单纯用"锚点行 == 产品行"→ 大量产品没图；
- 单纯用"垂直重叠面积最大"→ 高行会被上一行的图抢走（错得更离谱）。

实测有效的做法：
1. 用"大图列"（跨行的那张系列主图，from_row→to_row）划分**系列块**；
   没有大图列时整表作为一块。
2. 块内把产品行和图片锚点行**各自排序**，用双指针做单调就近分配：
```python
j = 0
for p in sorted(product_rows):
    while j + 1 < len(slots) and abs(slots[j+1] - p) <= abs(slots[j] - p):
        j += 1
    assign(p, slots[j])          # 少于产品数时天然复用，多于产品数时逐个命中
```
3. 多规格表（如"20暗装/26明装/15暗装"三列各有自己的图片列）要**按变体列分别配对**。
4. 图片列完全没覆盖的行，回退用该系列的"大图"。
5. 每行都复制一份图片文件（即使多行复用同一张源图），文件名按目标行号生成。

### 5. 一行拆多产品 / 子表要单独识别
- `型号` 为 `·` 或空 → 该变体不存在，跳过。
- 表里混着"系列价格子表"（列头与主表不一致，如按 SU7M/SU7F/SU7Pro 三列给价）时，
  按"同款不同系列价格"拆成多行，并在说明里标注。

## 标准流程

```python
# 1) 读 sharedStrings（注意反转义 &lt; &gt; &quot; &#10; 等）
# 2) workbook.xml + xl/_rels/workbook.xml.rels 建立 sheet 名 → sheetN.xml/drawingN.xml
#    注意：rId 与 sheetN 序号不一定对应，必须查 rels
# 3) 按上面的 CELL 正则 + mergeCells 回填 解析单元格
# 4) 解析浮动图片锚点(from_row/from_col/to_row/embed) 与 DISPIMG
# 5) 按"系列分块 + 单调就近"配对，写图片（product_0001.ext 形式）
# 6) 输出前校验：主图列非空数 == 图片文件数；目录无多余文件；必填项缺失清单
```
解析大文件（>100MB）时把 `parse_cells(sheet)` 结果做缓存，否则重复解析会让脚本从 15 秒变成十几分钟。

## 交付时务必附上的东西
- 一个"源数据对照"页：源工作表名 / 源行号 / 源型号 / 源系列 / 源颜色 / 源规格 / 源备注 / 图片文件名 / 图片匹配方式（精确命中 or 邻近匹配）。
- 一个"转换说明"页：每个数字的来源与口径、留空的列及原因、必填项缺失清单、"待确认"分类清单。
- 一个图片对照预览 HTML（Pillow 生成缩略图、base64 内嵌，自包含），让用户肉眼核对图片配对。

## 注意
- 不要为了让"必填项"好看而编造源表里没有的数字（价格/尺寸/日期），留空 + 清单列出来。
- 批量删除旧图片会触发安全删除拦截；直接原地覆盖同名文件即可。

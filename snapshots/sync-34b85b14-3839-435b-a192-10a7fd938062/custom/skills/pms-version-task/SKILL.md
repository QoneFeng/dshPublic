# PMS Version Task

在 PMS 版本详情的“需求列表”中执行完整流程：

`资格过滤 → 添加任务 → 工时登记 → 进入开发 → 提交测试 → 结果回读`

以页面流程为标准操作路径；PMS 登录态、对象解析、状态流转和结构化回读遵循 `pms-workflow`。

## 常用提示词参考

当用户询问如何使用本技能、需要可复制的调用示例，或只提供版本地址而需要整理目标需求输入时，读取 [references/usage-examples.md](references/usage-examples.md)。实际执行仍以本文件的资格过滤、恢复条件和安全规则为准。

## 依赖技能与安装

本技能依赖以下两个技能，缺一不可：

- `pms-workflow`
  - 用途：验证 PMS 登录态、读取版本与需求、查重、状态校验和结果回读。
  - 安装地址：[https://skillhub.3weijia.com/space/global/pms-workflow](https://skillhub.3weijia.com/space/global/pms-workflow)
- `playwright-workflow`
  - 用途：打开版本页面，操作需求列表、任务创建、工时登记、进入开发和提交测试弹窗。
  - 安装地址：[https://skillhub.3weijia.com/space/global/playwright-workflow](https://skillhub.3weijia.com/space/global/playwright-workflow)

执行前确认 `../pms-workflow/SKILL.md` 和 `../playwright-workflow/SKILL.md` 存在。缺失时停止操作，给出安装地址，安装后重新读取并完整遵循依赖技能。

## 优先执行脚本

优先使用 [scripts/pms_version_task.js](scripts/pms_version_task.js)。脚本默认只预览和校验（dry-run，不写入 PMS），只有用户明确要求执行时才增加 `--execute`。

```powershell
$env:NODE_PATH = node <playwright-workflow-scripts>\browser_ensure_playwright_runtime.js --print-node-path
$versionUrl = '<完整版本 URL>'
node scripts\pms_version_task.js `
  --version-url $versionUrl `
  --requirement '<需求编号或完整标题>' `
  --current-user-id <当前用户ID> `
  --current-user-name '<当前用户姓名>'
```

核对预览和校验结果中的版本、需求、当前账号、需求状态、版本测试负责人、重复任务和工时参数后，复用相同参数增加 `--execute`。

上一次由本技能执行时已创建任务，但在工时登记、进入开发或提交测试阶段中断时，先仅预览和校验（dry-run）确认同名任务唯一、执行人为当前账号，再显式增加 `--resume-existing`。不得把该参数用于任意旧任务。

## 输入与默认值

必须提供：

- `version_url`：PMS 版本详情 URL。

目标需求可用需求编号或完整标题指定。只提供版本 URL 时，先读取需求列表并执行资格过滤：

- 只有一条符合条件时，可直接选中并在结果中说明。
- 有多条符合条件时，列出候选需求并请用户指定，不得默认处理整个版本。
- 没有符合条件的需求时，只返回过滤结果，不执行任何写操作。

默认值：

- `task_title`：目标需求标题。
- `today_work_hours`：`5`，范围 `0–24`，最多一位小数。
- `latest_progress`：`100`，范围 `0–100` 的整数。
- `today_remark`：不填。PMS 强制要求时暂停并请用户补充，不编造工作记录。

## 执行资格过滤

任何写操作之前，必须同时满足两个条件：

1. 需求 `assignedTo` 等于当前 PMS 登录账号的用户 ID。
2. 需求 `status = 4`，PMS 页面实际文案为“已排期待开发”。用户口述“已排版待开发”时也按此状态理解。

任一条件不满足时，结果标记为 `skipped-ineligible`，并返回实际指派人、实际状态和不符合原因。禁止创建任务、登记工时或变更需求状态。

每条需求在 dry-run 和 execute 时都要重新校验，不得复用旧列表的过滤结果。

唯一例外是本技能的显式恢复模式：初始执行已在 `4 / 已排期待开发` 通过资格校验，且已成功进入 `7 / 开发中` 后中断时，`--resume-existing` 可仅继续“提交测试”。恢复前必须确认同名任务唯一、开发人为当前账号、测试人为当前版本测试负责人。

## 版本与身份校验

1. 只接受 `pms.3weijia.com` 的版本详情地址；测试环境必须由用户明确指定。
2. 从路径 `versionDetail_<id>` 和查询参数 `id=<id>` 解析版本 ID；两者不一致时停止执行。
3. 按 `pms-workflow` 验证 storageState 和 PMS 登录态。
4. 解析当前账号用户 ID 和姓名。storageState 缺少 `pdcaUserId` / `pdcaUserName` 时，只向本次 Playwright context 补入已确认身份；不把猜测值写回长期凭证。
5. 从 `/pdca/version/getVersionById?versionId=<id>` 动态读取 `qaByUser` 和 `qaByUserName`，作为本次需求的测试人。不得硬编码或使用版本创建人代替。
6. 按需求编号优先、完整标题其次唯一定位。页面操作必须锁定该需求的单张 `.sell-con` 卡片，不得把整个 `.list-item-con` 当成目标行。
7. 读取类 GET 接口返回“系统内部异常”时，允许最多 3 次短间隔重试。任务创建、工时保存和状态流转等写请求不得自动重试。

## 添加任务

通过资格过滤后，对每个目标需求串行执行：

1. 在需求列表中找到唯一目标卡片，点击“任务”展开任务区。
2. 读取已有任务。同一需求下已存在同名任务时默认跳过，不重复创建，也不基于任意旧任务自动推进需求状态。只有上一次本技能部分成功后，才使用 `--resume-existing` 恢复同一条唯一任务。
3. 点击“添加任务”。
4. 只填顶部“请输入任务名称”；不编辑左侧富文本描述。
5. 产品线、任务类型、优先级、指派给、计划时间、预计工时、项目、迭代、版本和关联需求全部保留页面默认值。
6. 保存前确认默认“指派给”是当前登录账号。不一致时停止，不自动修改。
7. 点击“保存”，不点击“保存并新增”。
8. 保存后回读新任务编号、标题和执行人。

## 工时登记与进度更新

1. 在新建任务行点击“工时登记”。
2. 把“今日累计投入”填为 `today_work_hours`，默认 `5`。
3. 把“最新进度”填为 `latest_progress`，默认 `100`。
4. “今日累计投入”是当天累计值，不是追加值。当天已登记值高于准备填写的值时停止，避免降低已有记录。
5. 保存后回读 `/pdca/task/getTaskBeforeUpdatedDetail?id=<taskId>`，确认 `todayWorkHours` 和 `todayCompletionRate`。

## 需求进入开发

任务建立且工时登记成功后：

1. 点击目标需求的“已排期待开发”状态按钮。
2. 选择“进行开发”，确认弹窗标题为“进入开发”。
3. 只主动设置：
   - “开发”：当前 PMS 登录账号。
   - “测试”：当前版本的 `qaByUser` / `qaByUserName`。
4. 产品经理、计划提测时间、计划发布时间和工时等其他字段保留 PMS 默认值。
5. 保存后回读需求详情，必须同时确认 `status = 7`、`devByUser = 当前账号`、`testByUser = 版本测试负责人`。

## 提交测试

1. 刷新需求列表，确认目标需求已是“开发中”。
2. 点击“开发中”，选择“提交测试”。
3. PMS 会校验是否存在未完成的开发类子任务。校验不通过时停止，不绕过。
4. 确认“提交测试”弹窗中的“指派给”和“测试”都已默认为版本测试负责人。PMS 控件可能显示姓名，也可能显示精确用户 ID；两者任一与 `qaByUser` / `qaByUserName` 一致即可。
5. 不修改弹窗内容，直接点击“保存”。页面要求选择分支、编译版本或其他必填内容时停止，不自行填造。
6. 保存后回读需求详情，必须确认 `status = 18`，页面状态为“待测试”，并返回 `actualSubmitTestTime`。

## 批量与安全规则

- 多个需求逐条完成全流程，不先批量创建再统一登记。
- 每条需求都必须独立通过“指派给当前账号 + 已排期待开发”过滤。
- 单条失败时不猜测操作；保留已成功的中间结果并说明失败阶段。
- 已创建任务但工时、进入开发或提交测试失败时，不删除任务。
- 不使用坐标点击，优先使用可见文本、角色、标签和当前需求卡片作用域定位。
- 不输出 token、cookie、storageState 或页面敏感凭证。
- PMS 接口只在 `pms-workflow` 已记录或已通过页面请求确认时使用，不猜测 payload。

## 成功标准

每个目标需求同时满足以下条件才算完成：

1. 需求在写操作前为当前账号指派，且状态是 `4 / 已排期待开发`。
2. 任务创建页只填写了任务名称，回读执行人是当前账号。
3. 工时登记保存成功，默认当天累计投入为 `5`、最新进度为 `100`。
4. 需求成功进入 `7 / 开发中`，开发人是当前账号，测试人是版本测试负责人。
5. “提交测试”弹窗未被修改，直接保存成功。
6. 最终回读状态为 `18 / 待测试`。

最终按需求返回：版本名称与链接、需求编号与标题、资格过滤结果、任务编号与标题、执行人、今日投入、最新进度、开发人、测试人、最终需求状态、实际提测时间，以及成功、跳过或失败原因。

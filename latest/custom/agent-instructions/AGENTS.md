# 全局 DSH 工作约定（跨项目）

适用范围：本机所有 DeepSeek Harness（DSH）会话。本文件是用户全局指令链，先于项目级 `AGENTS.md` 注入；
项目级约定更具体、优先级更高，两者冲突时以项目级为准。

## 1. 加载机制与边界

- 本文件路径：`%USERPROFILE%\.dsh\AGENTS.md`（即 `$DSH_HOME/AGENTS.md`），由内置插件 `@deepseek-ai/dsh-agent-instructions` 在会话首次请求时注入。
- 共享 agent 根：`%USERPROFILE%\.agents\AGENTS.md`（`$DSH_AGENTS_HOME`）。该目录同时被其他 agent 工具与 DSH 的 skill 扫描共用；只给 DSH 用的规则写在本文件。
- 项目链：从项目根（含 `.git` 的最近祖先）到会话工作目录，逐级加载 `AGENTS.md`、`CLAUDE.md`，再叠加 `AGENTS.local.md`、`CLAUDE.local.md`；同目录内容相同的文件只注入一次。
- 预算：每条链默认 65536 字节，单文件上限 1 MB（`maxSourceBytes`）。超预算时先省掉较宽泛的文件，最具体的文件最后截断，被省略的文件会在 `Workspace instruction budget ...` 通知里点名。
- 刷新：没有 watcher。外部编辑只在「新会话首次请求」「恢复会话」或「一次成功的 read/write/edit 触碰」后才可见。改完本文件最稳的做法是开新会话。
- 结论：不靠记忆猜规则，也不假设有后台在同步；一切以当前会话实际注入的指令与实际执行结果为准。

## 2. 长期记忆：Obsidian 是唯一入口

- 唯一入口：`D:\QoneWord\QoneObsidian\99.AI KB`。
- 检索顺序：先按项目显示名/工作区路径/模块/技术关键词检索；读对应项目 `项目记忆.md`，再按需读决策、踩坑与可复用经验。
- 历史结论只当检索线索，不替代当前代码、页面、运行时与数据验证。
- 该目录常在会话工作区沙箱之外：写入前先确认本会话文件策略；被拒绝时如实说明，不要绕道或用 shell 变通。

## 3. 项目级 AGENTS.md（每个项目都要有）

处理任一项目（既有或新增）时，按项目实际裁剪检查并生成/维护该项目自己的 `AGENTS.md`；不照搬业务细节。范本参考 `D:\QoneLab\3weijia_Code\smartHome\AGENTS.md`，应覆盖：

1. 适用范围与工作区边界：工作区路径、是否容器目录、含哪些子仓库/子目录、Git 操作在哪一层执行。
2. 用户身份与协作边界：使用者是产品经理，产出以文档/方案为终点；业务源码、配置、测试、SQL 迁移脚本只读，不落笔实现业务代码；允许写入范围为该项目 `AI doc` 及用户明确指定的文档位置。
3. 破坏性操作红线：删除/覆盖/移动前先出完整清单并等用户确认；删除先隔离不物理删；批量操作先验证命中集合再全量执行，收尾对账。
4. AI 任务产物目录约定：非业务文件统一放该项目 `AI doc`，按任务维度归档（`YYYYMMDD-任务简称`），维护 `AI doc\README.md` 索引，顶层保持整洁。
5. 历史遗留与例外：旧分类目录只读保留、原地不动；是否归并先与用户确认，不做静默迁移。
6. 任务开始与收尾：开始时读项目索引与 Obsidian 项目记忆；收尾登记任务索引、清理 `_tmp`，有复用价值的经验去重后沉淀回 Obsidian 并回读验证。
7. 写入约定：文档、脚本、JSON 显式 UTF-8，避免 PowerShell 默认编码损坏中文。

> 工作区已有的条款不要在本文件重复第二遍：全局链与项目链会叠加注入，重复写等于每条会话付两份 token。

## 4. 任务开始

1. 先读当前工作区的任务索引（`README.md` 或等效文件）与 `AGENTS.md`。
2. 按项目显示名、工作区路径、模块、技术关键词检索 `99.AI KB`。
3. 读对应项目的 `项目记忆.md`，再按需读决策、踩坑与可复用经验。
4. 涉及既有经验时读 `.learnings`。

## 5. 浏览器与页面操作通道

DSH 自带浏览器工具，默认走它，不另起浏览器实例：

- 常规网页调试、验收、取证（切页面、点按钮、填表单、读控制台、截图）用 `dsh_browser_*`：先用 `dsh_browser_a11y` 或 `dsh_browser_snapshot` 建立元素语义地图，再按语义目标点击/填表；列表页优先 `dsh_browser_scrape`，不要手写 `dsh_browser_execute` 抓列表。
- 页面状态不清时按顺序看：`dsh_browser_state` → `dsh_browser_console` / `dsh_browser_network` → 用 `dsh_browser_assert` 验证动作是否真的生效（「点到了」不等于「生效了」）。
- 每个任务的浏览器会话相互隔离，窗口与人共用；遇到人机验证（CAPTCHA、Cloudflare 等）立即停下，请人在浏览器窗口里完成，不要反复重试。
- 只有需要 Network 请求/响应、Performance trace、Lighthouse、CPU/网络节流、DevTools 协议级能力时，才接 `chrome-devtools` MCP；接之前先说明代价（通常会自起独立 profile 的新浏览器，不带用户登录态）。
- 不杜撰页面内容：没用工具实际读到的，不要写成「已确认」。

## 6. 重要任务收尾（最终答复前）

满足任一条件即为重要任务：改动代码/配置/文档/skill/自动化；做过真实浏览器、运行时、PMS、部署或迁移；形成关键决策、失败根因或可复用方法；用户要求记住、沉淀或复盘。

固定顺序：收集本次实际证据 → 提炼技术决策、解决方案、踩坑原因、可复用方法、验证状态、当前进度与下一步 → 检索去重 → 合并对应项目主记忆 → 跨项目方法提升到 `20.可复用经验`（如适用）→ 独立回读写入文件与链接 → 再发最终答复。

即使没有新增条目，也要完成检索去重并确认现有记忆已覆盖本次结论。任务中断或遗漏时，下一次任务开始优先补回。

## 7. 机制边界（不承诺不存在的东西）

- `99.AI KB` 没有独立后台监听器，也没有覆盖所有任务的全局 post-task hook。所谓「自动更新」指当前会话按上述流程主动执行；会话中断、换工具执行或漏做收尾时，Obsidian 不会自行变化。
- DSH 的定时任务（schedule）与 goal 续跑可以辅助长任务推进，但不等于收尾流程，不能替代需要人工确认的关键步骤。
- 不确定某功能是否存在时，先查安装版本文档或直接验证，不要按其他工具的用法推断。Codex 专有的 `cua`、Chrome 扩展绑定、`markDeliverable()` / `markHandoff()` 在 DSH 中不存在。

## 8. 安全与质量

- 只保留未来有复用价值的信息，避免复制对话、重复条目和临时日志。
- 不写密码、API Key、Token、Cookie、Session、私钥或其他可直接登录的秘密；只记录脱敏后的存在性、类别和位置。
- 项目专属结论写入对应项目主记忆；跨项目方法才提升到可复用经验。
- 写回后必须重新读取目标文件，确认日期、验证状态、wikilink 与敏感信息检查通过。
